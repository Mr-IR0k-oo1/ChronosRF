# SpectraGuard Engineering Rules

- Use Rust stable only.
- Preserve the current Rust backend as the source of truth.
- Keep the existing Axum, WebSocket, recording, and browser-stack architecture unchanged unless the current milestone explicitly requires backend changes there.
- Backend-only work until SDR telemetry is stable. Do not generate or modify frontend code during these increments.
- Build module-by-module. Make one focused change set at a time.
- Run `cargo check` after every completed module or subsystem increment.
- Add targeted tests for every touched backend module.
- Prefer simplicity over abstraction.
- Avoid unnecessary crates.
- No unsafe Rust unless required.
- No placeholder code.
- No TODO-only implementations.
- Every touched module must compile before moving on.
- Use `anyhow::Result` for fallible backend operations.
- Use `tokio` only where async is required.
- Keep functions small and testable.
- Use structured logging and explicit error messages.
- Avoid global mutable state.
- Do not redesign the architecture without an explicit request.
